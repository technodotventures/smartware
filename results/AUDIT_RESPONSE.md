# Response to the independent audit (results/AUDIT.md)

Every issue raised was accepted. Pre-audit artefacts are preserved unchanged in `results/v1/` so the before and after can be compared.

| # | Issue (severity) | What changed |
|---|---|---|
| 1 | Dialogue expansion leaked inadmissible text, also across tenants (critical) | Expansion and every neighbour feature now use the nearest **admissible** unit in thread order; threads are keyed by `(tenant, thread)`. Tests: `test_M45_expansion_only_admissible`, `test_M03_tenant_is_hard_boundary_even_for_admins`. |
| 2 | Inadmissible memories shaped ranking (critical) | BM25 statistics (N, df, average length), window and thread aggregates, entity damping, PRF and role detection are computed over the admissible set; ties are broken by position among admissible units. New normative rule (§5.1, M67): recall must equal recall over the store with the asker's unreadable memories removed. Test `test_M32_M33_M54b_M66_M67_identical_to_store_without_inadmissible` checks exact equality for three granularities; ORP-Gov v2 measures it on LoCoMo (`rank_side_channel`). |
| 3 | Conformance claim false (critical) | Every MUST now carries a stable id in the spec (`[Mnn]`), `tools/musts.py` regenerates `spec/MUSTS.md`, and each MUST maps to at least one test (68 MUSTs, 0 untested; M57 not applicable: no connectors ship). The engine was fixed wherever a probe failed: validity windows, time-travel labels, evidence never superseded, version bumps, `sources` on derived records, interval `event_time`, upsert requires `if_version`, enum rejection, path-based `scope.within`, `kinds` quotas, `granularity`/`include.neighbours`/`include.drafts`/`scope.prefer` honoured, `request_id` and `degraded` on every response, features in `why`, snapshot changes on every mutation, secret gate on every verb and inherited by derived records, redact clears derived metadata, export applies edge closure, audit log restricted to auditors. 83 tests pass. |
| 4 | Headline over-generalised to named products (major) | Tables label baselines "LLM-free re-implementation of the recall path". The limitations section states that no real product was run. |
| 5 | Asymmetric optimisation budget (major) | Each baseline engineer exposed 2-4 documented knobs (`TUNABLE`, ≤24 combinations, defaults unchanged); `bench/tune_baselines.py` tunes every baseline on the same dev splits with the same objective as ORP. Results report both default and dev-tuned baselines. `orp-rrf` (no learned model) and `orp-ablate` (learned ranker without position/length features) are reported next to `orp`. |
| 6 | LongMemEval dev/test contamination, non-standard haystack (major) | Distractors are now drawn only from sessions owned by questions of the same split (LME-R); dev haystacks share only the 4 evidence sessions the dataset itself shares across splits. The benchmark is named "LME-R (LongMemEval oracle, recombined)" everywhere. |
| 7 | QA rerun undisclosed, pipeline unscripted (major) | `bench/qa_blind.py` scripts batching, judging and scoring; the protocol and briefs are in `bench/qa_briefs/` and the v1 Haiku run is disclosed there. |
| 8 | QA blinding cosmetic; ORP showed dataset session ids (major) | The ORP adapter labels threads `S1..Sn` by order, never with dataset ids. Batches never contain two items of the same question. Each system keeps its own rendering (that is part of what is being tested); this is stated as a limitation. |
| 9 | Token counter penalised punctuation-heavy formats (major) | Primary metrics now count tokens as characters/4 (format-neutral). The original counter is kept as a secondary (`s_`) metric. |
| 10 | Stop-at-first-overflow packing disfavoured large items (major) | Primary metrics use greedy skip-and-continue packing. Stop-at-overflow is the secondary metric. |
| 11 | Governance benchmark circular, table stale (major) | ORP-Gov v2 adds mixed-ACL threads, a second tenant with identical thread ids, leak detection on returned **text** (shingles that occur only in unreadable units), a ranking side-channel measurement, a global-statistics strategy, and a correctly implemented post-filter. Results are regenerated by `bench.report`. |
| 12 | "Scored once" unverifiable; encoder not reproducible (major) | Raw per-query results are tracked in git; `bench/train_encoder.py` rebuilds the encoder (sha256 in `results/ENCODER.sha256`); `bench.run` appends every test invocation with the git hash to `results/TEST_RUNS.log`. |
| 13 | Time validity broken (major) | `valid_from ≤ as_of < valid_to` is enforced exactly for every kind; time-travel hits are labelled current; tests M20, M35, M35b. |
| 14 | Secret gate post-ranking and missing on get/neighbours (major) | Labels are part of admissibility; `get`, `neighbours`, `export` and `profile` use the same check. |
| 15-20 | Minor engine issues | Fixed as listed in row 3. |
| 21 | Unsourced claims about other projects in the spec | Moved to Appendix C with report section references; the normative text no longer makes claims about other projects. |
| 22 | Feature count misstated | Reported from the shipped model (`results/orp_params.json`). |
| 23 | Latency measured under contention | Latency is reported from a separate single-process run. |
| 24 | Baseline spot-check notes (Graphiti limit, mem0 phatic skip) | Graphiti's `limit` (10 or k) is a tunable knob; other notes are recorded in the limitations. |
| 25 | Test hygiene | Sockets and subprocesses are closed. |

Not addressed, and why:
- Running the real products (e.g. mem0 with `infer=False`) as anchors: the sandbox has no package registry access, so the projects cannot be installed. This remains the main limitation.
- The shared encoder is trained on all benchmark text (unsupervised, label-free, shared by every system). This is stated plainly rather than changed, because a dev-only encoder would be too weak to be informative.
