// why smartware

Most memory was built for chatbots. Agents need more.

Agents act on what they remember, often for many users at once, inside a fixed context window. Smartware is the next step in frontier research on how autonomous agents learn and remember, and it closes the three gaps that hold agents back.

Stale facts

Ask "where does Maya live now?" and most memory layers return her old address and her new one, unranked. An agent acting on the wrong one makes a real mistake.

SmartwareEvery fact knows when it was true. Old versions are marked superseded, so your agent gets the current answer, or the answer as of any date.

Leaky recall

Filtering permissions after ranking quietly drops good answers, and a summary built from a private message can surface to the wrong user.

SmartwareAccess is checked before anything is ranked. A summary is never more visible than its most private source. Zero leaks in our multi-tenant test.

Context bloat

Recall returns ten hits and hopes they fit. No token budget, no citations, no way to say "nothing relevant here".

SmartwareAsk with a token budget and get a context pack that fits it, with a citation and a reason for every item, ready to drop into the prompt.

// how it works

One call. Exactly the context your agent needs.

Your agent calls recall with a question, a point in time and a token budget, from any model or framework over MCP or HTTP. Smartware returns the current facts that fit, each with its source and the reason it made the cut.

POST /v1/acme/recall 
{
  "query": "Where does Maya live now?",
  "as_of": "2026-06-30",
  "budget": { "tokens": 1500 },
  "include": { "history": true,
               "explain": true }
}

// the principal comes from your API key,
// never from the request body
from smartware import Smartware

mem = Smartware(tenant="acme", key="…")

pack = mem.recall(
    "Where does Maya live now?",
    as_of="2026-06-30",
    budget=1500,
)
prompt = pack.render()  # drop into context
{
  "mcpServers": {
    "smartware": {
      "command": "smartware",
      "args": ["mcp"]
    }
  }
}

// foundations

Four rules at the foundation.

Written into the protocol and tested on every change. They never bend, so your agents can build on them.

Three clocks

Every memory separates when it was learned, when it happened and when it was true. Your agent can ask what was true on any date, or what it knew at the time it acted.

observed
happened
valid

Permissions before ranking

Access is checked before anything is scored, on every channel. One Smartware can serve every user and tenant your agents work for, and a private DM can't leak through a digest.

DM · hr only#general · all→summary · hr only

Explicit supersession

When a fact changes, the old version is marked superseded and linked to the new one. Nothing is quietly overwritten, so you can always see what your agent believed and why.

Forgetting that sticks

Retract, redact or purge, with a dry run first. Forgetting cascades to every summary built from that memory and blocks it from coming back, which is what deletion requests actually need.

// self-improving

Smartware improves itself with autonomous research loops. Every week its agents read the frontier, turn your feedback and requests into hypotheses, run the experiments and keep only what beats the last best. Every loop leaves it a little smarter, and you get each gain by upgrading, with nothing to tune.

    Only better ships

    A change merges only if it beats the current version on the benchmarks and every MUST in the spec still passes.

    Agents never grade themselves

    The keep-or-revert call is plain, deterministic code, not the agent that wrote the change.

    Humans sign the spec

    Agents improve the engine freely. Changes to the protocol itself need a maintainer's approval, so your integration never breaks.

    Every change has a reason

    Each release links the research, feedback or request behind it, with the benchmark run and the diff, in public.

      // user-owned · agent-led · open

      User-owned. Agent-led. Open protocol.

      Your memory belongs to you: host it yourself or anywhere, and export every record losslessly at any time. Agents lead its development in the open, and the protocol is public: fourteen verbs, one record format and a test for every MUST. Any engine that passes works with every client and agent.
